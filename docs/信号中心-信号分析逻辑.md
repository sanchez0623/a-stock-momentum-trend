# 信号中心：信号分析的逻辑（深入浅出）

> 配套代码：`backend/app/core/indicators/`、`backend/app/core/signals/engine.py`、`backend/app/core/screener/engine.py`、`backend/app/core/config.py`
> 本文把"信号中心到底怎么想问题"讲清楚，不堆公式，重在逻辑。

---

## 0. 一句话先讲明白

**信号中心干一件事：把冷冰冰的 K 线和指标，翻译成你能直接做决定的"人话"。**

把它想象成你的「交易副驾」——它**不替你下单**，只干两件事：

1. **挑票**：在全市场里筛出"值得看"的票（选股打分）；
2. **定动作**：对你持有或关注的每一只票，告诉你"现在该干嘛"（信号引擎）。

这两步，就是"信号分析"的全部内容。下面拆开讲。

---

## 1. 信号分析的两条流水线

无论是挑票还是定动作，**底层原料都是同一套"指标"**。所以先说原料，再说两条线。

```
        K线数据 (open/high/low/close/volume)
                     │
                     ▼
            ┌────────────────────┐
            │   指标计算(纯函数)   │  ← 九件套：MA/EMA/MACD/RSI/ROC/ADX/布林/ATR/量比
            └────────────────────┘
                     │
        ┌────────────┴─────────────┐
        ▼                          ▼
┌──────────────┐          ┌──────────────────┐
│ 选股打分(挑票) │          │ 信号引擎(定动作)  │
│ 三因子40+40+20│          │ 五类信号优先级裁决 │
└──────────────┘          └──────────────────┘
        │                          │
        ▼                          ▼
   关注度分级 → 候选池        结构化信号 → 计划/复盘闭环
```

### 关键设计：指标是"纯函数"

`indicators/indicators.py` 里每个指标都是纯函数——**输入一段 K 线，输出一段带新列的 K 线，没有任何副作用**。

- 今天算、明天算、回放半年前算，结果一模一样；
- 正因如此，系统才能"回测""复盘""评分"——把历史上的信号重新跑一遍，检验当时该不该听它的。

> 一句话：指标是系统的"眼睛"，纯函数让这双眼睛永远看得准、看得可复现。

---

## 2. 第一层分析：选股打分 —— "这只票值不值得看"

文件在 `screener/engine.py` 的 `score_indicators()`。它给每只票打一个 **0~100 的总分**，拆成三因子：

| 因子 | 满分 | 怎么算 | 看什么 |
|------|------|--------|--------|
| **趋势分** | 40 | ADX 强度(0~20) + 均线多头排列(0~20) | 有没有"方向" |
| **动量分** | 40 | ROC(0~15) + RSI 位置(0~10) + MACD 红柱(0~15) | 涨得"猛不猛" |
| **量能分** | 20 | 量比(0~10) + 量价配合(0~10) | 是不是"真金白银"在涨 |

总分再映射成**关注度**四级：

- `≥70` 强烈关注 ｜ `≥60` 重点观察 ｜ `≥50` 一般关注 ｜ `<50` 观察

### 一个很妙的细节：理由和分数"同源"

注意看代码——`_build_reason()` **不重新算指标**，它只把 `score_indicators()` 已经算好的数字"翻译"成人话（"均线多头排列""MACD 金叉""放量 2.3 倍"）。

> 这样做的意义：你看到的**理由永远不会和分数打架**。不会出现"分数很高但理由很弱"，或"理由写得很热闹但分数很低"的尴尬。分数和说法，永远来自同一份数据。

这就是"信号中心"区别于裸指标软件的地方：**它不只给数字，还给判断。**

---

## 3. 第二层分析：信号引擎 —— "这只票现在该干嘛"

文件在 `signals/engine.py` 的 `SignalEngine.evaluate()`。它针对**某一只具体票**（可带持仓、可带实时行情），产出**一条结构化信号**。

每条信号长这样：

```
type             信号类型
symbol/name      哪只票
direction        buy / sell
strength(0~100)  信号强度(越接近100越强烈)
reason           人话理由(比如"回踩20日线企稳,MACD未死叉")
indicators_snapshot  当时的关键指标快照(留痕,供复盘)
```

### 五类信号，各自的触发逻辑

| 信号 | 含义 | 触发条件（简化版） |
|------|------|--------------------|
| **BUY_FIRST** 首仓 | 第一次上车 | 趋势+动量+量能"三共振"，加权分 ≥ **60** |
| **BUY_ADD** 加仓 | 车上再加 | 已持仓且浮盈 + 回踩中期均线不破 + MACD 未死叉 |
| **SELL_REDUCE** 减仓 | 先落袋一部分 | RSI 顶背离 / 触及分批止盈档 / 价升量缩 |
| **SELL_STOP** 止损 | 认错离场 | 跌破止损线，或 短期均线下穿中期 + ADX 掉头 |
| **T_BUY / T_SELL** 做 T | 日内撸羊毛 | 需有底仓；冲布林上轨卖、踩布林下轨买，且日内波动够大 |

#### 首仓"三共振"长什么样

代码里首仓的加权打分跟选股同构（趋势 40 + 动量 40 + 量能 20），但更看重"共振"：

- **趋势**：ADX > 阈值(默认 25) 且 短>中>长 均线多头排列；
- **动量**：MACD 金叉(或 DIF>DEA) 或 ROC 由负转正，RSI 在 50~70 强势区加分；
- **量能**：量比 > 阈值(默认 1.5) 才算"放量确认"。

三项加权总分 **≥ 60** 才出首仓信号。低于线？宁可不出——**不凑信号，是纪律的一部分。**

---

## 4. 信号不是并列的：优先级裁决

这是整篇最关键的一点。五类信号**不是平铺排队**，而是**按"保命优先"的顺序依次判定，命中即返回，后面的不再看**：

```
① 止损 SELL_STOP   ← 最优先，保命
② 减仓 SELL_REDUCE
③ 加仓 BUY_ADD
④ 首仓 BUY_FIRST
⑤ 做 T T_BUY/T_SELL ← 需有底仓
```

**为什么止损排第一？** 因为"活着"比"赚钱"重要。一旦持仓触发止损条件，系统立刻返回止损信号，**后面的加仓、首仓、做 T 一律不再生成**——绝不会"一边喊止损一边又让你加仓"。

> 一句话：信号引擎的裁决逻辑，本质是**风控优先于进攻**。

---

## 5. 信号强度（strength）怎么来的

强度不是拍脑袋，而是各有算法：

- **首仓**：直接用三因子加权总分当强度（封顶 100）；
- **加仓**：`55 + 浮盈% × 5`，封顶 90——浮盈越多、加仓信心越强；
- **减仓**：顶背离 65 分，其它 60 分；
- **止损**：固定 **90**（最严重，几乎等于"立刻执行"）；
- **做 T**：固定 70。

强度让你一眼看出"这条信号有多急"，配合 reason 一起看，就知道是该马上动、还是再等等。

## 6. 配置驱动：所有阈值都你说了算

所有"魔法数字"都在 `config.py` 里，分组管理、可热更新（改完经 API 写库，信号逻辑立刻生效，不用重启）：

```yaml
趋势:   ma_short: 10, ma_mid: 20, ma_long: 60, adx_threshold: 25
动量:   macd_fast: 12, macd_slow: 26, macd_signal: 9, rsi_period: 14, roc_period: 12
量能:   volume_ma: 20, volume_ratio_threshold: 1.5
风控:   stop_loss_pct: 5.0, trailing_stop_pct: 8.0, ...
仓位:   金字塔比例 / 止盈档位(atr动态 or 固定)
做T:    enable, min_swing_pct: 1.5, ...
```

比如你觉得最近震荡多，把 `adx_threshold` 从 25 调到 30，系统立刻变"严"——只有趋势更明确才出信号。**这套逻辑是给你调的，不是写死的。**

## 7. 一个完整例子串起来

以"宁德时代(300750)"为例：

1. **选股打分**：盘后全市场扫描，它趋势 36 + 动量 31 + 量能 18 = **85 分 → 强烈关注**，进了你的候选池；
2. **信号引擎（你已持仓、浮盈 4%）**：
   - 先查止损：没破线 ✗
   - 再查减仓：没顶背离、没到止盈档 ✗
   - 再查加仓：回踩 20 日线企稳 + MACD 未死叉 ✓ → 出 **BUY_ADD 加仓信号，强度 ~77**
   - reason："回踩20日线企稳(现价 X,浮盈4.2%),MACD未死叉"
3. **计划生成**：把这条信号 + 你的仓位 + 风控，合成一份人话操作指引（加多少、触发价、止损价、止盈档、纪律提醒）；
4. **你执行 → 回填成交 → 评分/复盘**：下次 AI 复盘时，这条信号的对错会被单独追溯。

**信号中心 → 计划 → 执行 → 复盘**，这就是系统完整的决策闭环。

## 8. 选股到底基于什么逻辑？可信吗？

上一节讲了"分数怎么算"，但这里要正面回答一个更尖锐的问题：**它凭什么选这几只？凭什么信它？**

### 8.1 它基于什么逻辑

一句话：**纯技术面、动量/趋势导向的多因子排序**。它**不看任何基本面**，只看"价格 + 成交量"讲的故事。

- **输入**：每只票的日 K 线（最近 80 根，至少 40 根）
- **计算**：和信号引擎同一套指标（MA / MACD / RSI / ROC / ADX / 量比）
- **打分**：三因子 趋势 40 + 动量 40 + 量能 20 = 0~100
- **过滤**：剔除 ST / 退市；剔除近 20 日均成交额 < 5000 万的"僵尸股"
- **输出**：按总分排序的 Top N（默认 30），带关注度分级

所以它本质在回答一个问题：**"全市场里，此刻哪只票的技术面最像'正在走趋势'？"** —— 是"找形态"，不是"找价值"。

### 8.2 可信的一面（内部自洽、可复现）

- **和信号同源**：选股打分与首仓信号的因子完全一样。一只票能被选出来，基本就等于"如果现在看它，会触发首仓信号"。不会出现"选股说好、信号说别买"的矛盾。
- **理由不注水**：`score` 算完才翻译人话，理由永远跟着分数走，不会叙事比分数乐观。
- **纯函数可回测**：今天扫、半年后扫同一天数据，结果一致——你能把历史信号重跑一遍验证。
- **两道基础滤网**：ST / 退市 + 流动性门槛，挡掉最脏的坑。
- **趋势过滤**：ADX 把"震荡"和"真趋势"分开，避免把无方向波动当成机会。
- **量价配合加分**：放量且收阳才加分；放量却收阴反而提示"高位派发"。

### 8.3 不可全信的一面（盲区与风险）

- **纯价格，零基本面**：一只票可以业绩暴雷、估值离谱，只要技术上在涨就能上榜。选股不替你做"该不该买这家公司"的判断。
- **看的是"过去"，排的是"现在"**：打分只用最后一根 bar 的快照，是"谁现在最猛"，不等于"谁未来还会猛"。动量有持续性，但会衰减、会反转。
- **吃市场风格**：趋势/动量策略在单边市如鱼得水，在震荡市会被反复打脸（假突破）。ADX 阈值定松了接飞刀，定紧了错过启动。
- **权重是默认值，未经你的样本外验证**：默认 40/40/20 是拍的，调参去拟合历史 = 过拟合陷阱（系统文档也提示"提供样本外验证"）。
- **不叠加风控闸门**：选股本身不管当日亏损熔断、回撤、单票上限。高分票到了信号引擎 / 风控那一层，仍可能被拦下。
- **数据依赖上游**：评分质量上限 = 数据源质量。东财风控、缓存过期、复权错误都会让排名失真。

### 8.4 怎么用它才靠谱

把它当**"初筛漏斗"**，不是"圣旨"：

1. 它把 5000 只缩到前 30 只"技术面最像趋势"的票 → 进自选；
2. 你再用人脑补上它看不到的（业绩、消息、行业、大盘）；
3. 真要动，等信号引擎对这只票发出具体动作（首仓 / 加仓），且过风控；
4. 用复盘 / 评分回头检验"它选出来的票，后来到底准不准"，再决定要不要调阈值。

> 一句话：选股是**可信的初筛**，不是**可信的买卖**。它帮你"不漏掉形态"，但"买不买、买多少"永远是你的决定。

## 9. 选股器三处改进已落地（2026-08-08）

针对"选股还有改进空间吗"一节列出的优先级矩阵，已把左上「立刻做」的 ① ② ③ 三项改完，代码位于 `backend/app/core/screener/engine.py` 的 `score_indicators()`。改动都是**纯函数内部调整**，不改变接口与输出结构，三因子总分口径不变，只是让分数更"说人话、不打架"。

### ① MACD 评分按 ATR 归一化（消除绝对价位扭曲）
- **旧**：`macd_score = hist / 1.0 * 15`，`hist` 是 MACD 柱的绝对值（股价单位）。高价股轻易拿满、低价股凑不够，分数被价位绑架。
- **新**：`macd_norm = hist / atr14`（无 ATR 时回退 `hist / close`），再乘 15。分数变为"动量相对自身波动率的强度"，与价位脱钩。
- **验证**：同形态、价位 10 与 200 的两只票，`hist/atr` 比值均为 **0.1656**，动量分 **15.4 = 15.4**（旧代码会差十几分）。

### ② 读近 N 根 bar，判断趋势"持续度 / 加速度 / 连贯性"
之前 `score_indicators` 只取 `ind.iloc[-1]` 最后一根，80 根 K 线浪费了。现在新增：
- **ADX 斜率**：取 5 根前的 ADX 比较，只有"达标且仍在走高"才给满；达标但走平/回落，ADX 子分 ×0.7（趋势动能减弱）。
- **ROC 加速度**：取 3 根前的 ROC 比较，动量减速则轻微打折（×0.9）。
- **趋势连贯性**：近 20 日收盘站在短期均线之上的占比（`consistency`），≥0.8 且多头时打"趋势连贯"标签。
- 这些字段同时进 `_build_reason`，理由新增"ADX走高""趋势连贯"等标签，与分数同源。

### ③ ROC 过热衰减（让分数和理由对齐）
- **旧**：`roc_score = min(15, roc/5*15)`，涨幅越大分越高，但 `_build_reason` 却在 `roc≥20` 提示"追高需谨慎"——分数与理由自相矛盾。
- **新**：分段曲线——`0~8%` 健康区线性给满（15），`8~20%` 边际递减（15→10），`20%+` 追高区继续衰减到下限 3。分数开始"嫌弃"追高，与理由的追高预警一致。
- **验证**：温和 `roc=9.3%` → 动量分 24.4；过热 `roc=35.2%` → 动量分 **11.6**，且 reason 明确写出"近12日已涨35%，涨幅偏大，追高需谨慎"。

> 这三项属于"消除逻辑矛盾 / 降噪"，不动选股的本质定位（仍是纯技术面动量初筛）。右上矩阵里同属"抬上限"的 ④ 市场闸门、⑤ 行业限配 **已经在本节之后落地**，详见第 11 节。

## 11. ④ 市场闸门 与 ⑤ 行业限配（已落地，2026-08-08）

把右上矩阵里"抬上限"的两块硬骨头补上了。两者都是**选股输出之后的后处理**：不改三因子打分，只在排名结果上做"缩放（闸门）"和"裁剪（限配）"。

### 11.1 ④ 大盘择时闸门：市场不好时少选几只

**解决什么**：选股器不理会大盘环境——熊市里它照样挑出一堆"技术面最像趋势"的票，但系统性下跌时这些票大概率一起挨揍。闸门在**扫描前**先看一眼大盘牛不牛，不牛就把 `top_n` 按比例缩掉（默认熊市只留 30%）。

**阀门怎么选（配置驱动、可多指数、可换板块）**：
- 配置 `择时闸门.reference_indices` 是一组参考指数，每个带 `name` + 东财 `secid`（如 `沪深300=0.000300`、`创业板指=0.399006`、`上证指数=1.000001`）。
- 每个指数独立判"多头排列"：收盘站上 `MA200` 且 `MA60 > MA200`；满足即该指数看多。
- 汇总：`bull_count / N` → 环境 `bull / bear / neutral`，再映射乘数：
  - 全多 → 不缩减（`bull_top_n_ratio=1.0`）；全空 → 缩到 `bear_top_n_ratio`（默认 0.3）；一半一半 → 折中。
- **不同板块想用不同阀门？直接改 `reference_indices` 即可**——想跟创业板行情就把创业板指放前面、甚至只留它。系统对"选哪几个指数"完全开放，不写死。

**板块数据哪里来**：阀门用的是**指数 K 线**，不是个股板块。数据走已有的 `DataSourceManager.get_index_kline(secid)`，底层路由东财源（secid 东财格式），与个股 `get_kline` 共用缓存/熔断/降级，**不需要新接口**。

**诚实边界**：这是"最小版"——只用宽基指数做**全市场统一**的一个乘数，并不"按板块分别给不同阀门"（那需要板块动量，见 11.4）。它的定位是系统性风险的总闸，不是行业轮动。

### 11.2 ⑤ 每行业限配：同一行业别挤太多只

**解决什么**：动量策略容易扎堆——同一条主线（如半导体）可能在前 30 名里占一大半，组合过度集中。限配让每个行业最多留 N 只，逼组合分散。

**行业怎么定义（可配置到申万三级）**：
- 配置 `行业限配.level` 取 `sw_l1 / sw_l2 / sw_l3`，对应**申万一级/二级/三级**行业。
- 行业标签来自新增的 `StockClassification` 表（落库持久化），每只票带 `sw_l1/sw_l2/sw_l3` 三级 + 行业/概念板块列表。
- 调 `level` 切换颗粒度：粗分散用 `sw_l1`（31 大类），细分散用 `sw_l3`（335 细分）。

**限配怎么算**：扫描结果**按总分降序后**，按所选级别分组、每组从头截到 N 只；**未知行业（无标签）不限额**，避免误杀。纯内存后处理。

### 11.3 接口是否够用 / 性能如何

| 需求 | 数据来源 | 是否需新接口 | 性能代价 |
|------|----------|--------------|----------|
| ④ 宽基指数 K 线 | `DataSourceManager.get_index_kline`（东财，secid 直通） | **否**，复用现有 K 线通道 + 新增 `secid` 透传 | 扫描前**额外拉几次指数 K 线**（几个指数就几次，非全市场），O(常数)，可忽略 |
| ⑤ 申万 L1/L2/L3 + 板块 | 新增 `StockClassification` 表，由 akshare（`sw_index_*_info` / `stock_board_*_em`）一次性刷新落库 | 刷新需新接口（已加 `POST /screener/classification/refresh`），但**扫描时零额外调用**——只读本地表 | 扫描时一次 `WHERE symbol IN (...)` 批量查询，O(结果数)，可忽略 |
| ⑤ 分组截断 | 内存分组 | **否** | O(结果数)，可忽略 |

**性能结论**：两项改造都落在"扫描前一次性拉指数"和"扫描后内存后处理"两端，主瓶颈——5000 只票**逐只串行拉 K 线打分**——完全没动。闸门与限配对单只扫描耗时**零增量**。

### 11.4 诚实边界与下一步

- `refresh_classification` 依赖 akshare 在线拉申万/板块成分股，**首次需联网**（沙箱因代理限制跑不通，需在真实环境执行一次）；刷新后日常扫描只读本地表。
- ④ 是宽基总闸，不是行业轮动阀门。想要"板块级各自择时"，数据上可行（板块成分股已知，可聚合板块强度），但属于下一阶段：需新增"板块动量评分"再驱动各自的 multiplier。
- 验证现状：纯函数 `compute_market_gate` 与 `apply_per_industry_cap` 已用合成数据单测覆盖（`tests/test_gates_pure.py`，12 用例全过）；申万 L1 落库质量需在真实环境跑一次 `refresh_classification` 后，经 `GET /screener/classification/stats` 核对覆盖度再确认。
- 还可这样验证"④⑤ 真的用上了且有效"：
  - **后端 INFO 日志**：每次扫描会打印闸门环境/乘数（含"未启用"也打印，确认接通）与限配触顶组明细（`电子:12→3` 这种），直接看是否参与。
  - **`GET /api/screener/last-scan-summary`**：把最近一次扫描的闸门环境、乘数、有效 top_n、限配前后只数、触顶行业汇总成 JSON 返回（内存态，服务重启后丢失，返回 `scanned_at=null` 占位）。前端可据此在界面直接展示，不必翻日志。
  - **`scripts/verify_gates.py`**：纯合成数据、零依赖，演示整条链路 before/after（`cd backend && python ../scripts/verify_gates.py`）。
  - **集成测试 `tests/test_scan_summary.py`**（2 用例全过）：用 mock 直接跑 `screener.scan()`，断言汇总里 gate（牛市乘数 1.0、环境 bull、details 非空）与 cap（6 只→每组 2→4 只、触顶 2 组）正确，且全关时 `final_count=6` 不被缩减。

## 10. 小结（记住这张网就够了）

```
指标(纯函数,可复现)
   ├─ 选股打分(三因子)  → 关注度分级 → 候选池   【挑票】
   └─ 信号引擎(优先级裁决) → 五类信号(强度+人话+快照) → 计划/复盘  【定动作】
```

- **信号中心 = 眼睛(指标) + 脑子(两层分析) + 嘴(人话理由)**；
- **两层分析**：选股打分负责"看不看得上"，信号引擎负责"现在动不动"；
- **裁决铁律**：止损 > 减仓 > 加仓 > 首仓 > 做 T，保命优先；
- **一切可调**：阈值都是配置，逻辑因你而变；
- **闭环思维**：信号不是终点，是计划与复盘的起点。

> 最后一句提醒：信号中心只给建议、不替你下单。任何信号都只是概率优势，不是 guaranteed win。仓位管理 + 止损纪律，才是真正决定你活多久的东西。
