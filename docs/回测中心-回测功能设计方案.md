# 回测中心 — 回测功能设计方案 v2

> 状态: 设计稿 v2.0(重构) · 关联模块: `backtest` / `signals` / `position` / `tradelog` / `datasource.baostock` / `fees` / `stats`
> 背景: v1 已落地「阶段分桶因子回测 + 全流程策略回测」, 但存在**数据口径(动态前复权污染)与起点设定(只能用今天的股票池)**两大准确性问题。
> v2 重构目标: 回答「**我手上这些持仓, 按系统纪律管理到底会怎样**」——以真实持仓/指定建仓组合为起点做回测, 并新增信号审计量化「计划 vs 执行」偏差。

---

## 1. 为什么需要回测(保留 v1 核心结论)

技术面选股提供的是**概率优势**而非确定性: 动量/趋势类策略历史胜率通常 40%~60%, 赚钱靠盈亏比。
**期望值 = 胜率 × 平均盈利 − 败率 × 平均亏损**, 回测量化的是这个数。

| 问题 | 回测层次 | 直接产出 |
|---|---|---|
| Q1 不同分数段/阶段买入, 未来 N 日表现差多少? | 因子回测(已落地) | 分桶胜率表 |
| Q2 **我现在持有的票, 按系统信号管理 vs 躺平, 差多少?** | **持仓回测(v2 核心)** | 对照净值曲线 + 差异归因 |
| Q3 **我过去执行 vs 系统当时建议, 偏差亏了多少?** | **信号审计(v2 新增)** | 真实曲线 vs 纪律曲线 |
| Q4 五类信号触发后的历史表现如何? | 信号回测(演进) | 信号有效性报告 |
| Q5 完整策略(选股+信号+风控+仓位)历史净值与回撤? | 全流程策略回测(已落地) | 资金曲线报告 |

---

## 2. v1 现状诊断: 为什么「粗糙/不准确」

v1 已实现 `backtest/factor.py`(阶段分桶) 与 `backtest/strategy.py`(全流程策略), 问题不在功能缺失, 而在数据与起点:

| # | 缺陷 | 后果 | v2 对策 |
|---|---|---|---|
| 1 | **动态前复权污染**: K线缓存为腾讯 qfq, 历史价格随每次除权被重算; 且缓存参与日常增量刷新 | 用今天的缓存回测过去 = **未来函数**; 除权日价格跳变误触发止损 | §4 回测专用**冻结快照**数据通道 |
| 2 | **股票池是「今天的视角」**: 策略回测默认池=当前自选+持仓, 丢回 3 年前跑 | 幸存者偏差; 回答不了「这笔持仓当初该不该买/怎么管」 | §5 以建仓日为准的持仓回测 |
| 3 | **不能指定建仓时点**: 只能从空仓+信号自动首仓开始 | 无法回测「3月建仓某票按系统管理到现在」 | §5.2 组合回测(多股不同建仓日) |
| 4 | 日线缓存上限 800 根(~3.2 年) | 回测区间短 | §4 baostock 任意起止日期 |
| 5 | 无基准对比 / 无参数敏感性 / 行业限配未接入 | 结果无参照系, 无法判断超额 | §7.4 / §10 |
| 6 | **做T 两套逻辑**: SignalEngine 一套, strategy.py 内联一套 | 口径漂移, 回测与实盘信号不一致 | §7.2 统一 |
| 7 | 回测任务内存态, 重启丢失 | 体验问题 | §7.5 持久化 |

**v1 可复用的资产**(无需重写): `SignalEngine.evaluate_with_ind(ind, position, end)` 任意历史位置回放、`Position.opened_at/cost/qty/pyramid_stage`(建仓时间/成本/数量/加仓档位全齐)、baostock `query_history_k_data_plus`(任意起止日期+复权)、`compute_trade_fee` 成本模型、风控三道闸门。

## 3. 设计原则

1. **起点真实**: 回测从「真实建仓时点 + 真实成本」出发, 不把今天的持仓/自选丢回过去;
2. **数据冻结**: 回测用独立冻结快照, 不参与日常增量刷新, 杜绝动态复权未来函数;
3. **口径唯一**: 信号判定、做T、费用全部复用实盘同一套代码(SignalEngine / compute_trade_fee);
4. **对照优先**: 任何回测默认输出 3 条线——策略线 / 买入持有线 / 基准线, 只谈超额;
5. **参数覆盖**: 回测可临时覆盖配置(止损/止盈/仓位), 但不写回实盘配置。

## 4. 数据地基: 回测专用历史数据通道(前复权冻结快照)

### 4.1 表结构 `backtest_kline`

```
backtest_kline(
    id         INTEGER PRIMARY KEY,
    symbol     TEXT NOT NULL,        -- 6位代码(指数用 idx: 前缀)
    period     TEXT NOT NULL,        -- daily
    date       TEXT NOT NULL,        -- YYYY-MM-DD
    open/high/low/close REAL,
    volume/amount REAL,
    adjust     TEXT NOT NULL,        -- qfq(前复权) / raw(不复权), 回测默认 qfq
    fetched_at TEXT NOT NULL
)
-- 唯一索引 (symbol, period, adjust, date)
```

行式存储(非现有缓存的一整段 JSON), 因为回测按 symbol × 区间查询, 且要与实盘缓存完全隔离。

### 4.2 拉取与缓存策略

- **数据源**: baostock `query_history_k_data_plus`(支持任意 start_date/end_date, `adjustflag="2"` 前复权, 与腾讯/akshare qfq 口径一致);
- **触发时机**: 首次运行回测且区间超出实盘缓存范围时, 按需补拉; 补拉结果写入 `backtest_kline`(**不回写** `kline_cache`, 不污染实盘);
- **区间**: 默认近 3 年(约 730 根), 上限 5 年可配; 起始日期自动回退 120 根作为指标预热(MA60/MACD 需要);
- **增量**: 同 (symbol, adjust) 已拉过的日期直接复用, 只补缺; 区间内数据**冻结**, 不再随新除权重算(qfq 历史部分在快照后保持不变);
- **幂等**: 重复运行同一区间不重复拉取; 失败标记 `fetched_at` 为空可重试。

### 4.3 复权口径: 为什么选「前复权冻结快照」也能准确

- 回测标准口径是**后复权**(hfq), 但本项目所有源(腾讯/akshare/baostock)与券商 APP 均以前复权为默认;
- 前复权回测的「未来函数」风险**只来自动态刷新**(每次增量基于最新除权重算历史)。只要把回测区间数据**冻结为快照**, 区间内价格即恒定, 除权日跳变由 §4.4 防护兜底, 结果与后复权等价;
- 结论: **回测统一 qfq 冻结快照**; 若后续接入 hfq 源, 只需加一行 `adjust="hfq"` 分支, 引擎无感。

### 4.4 降级与防护

- 优先读 `backtest_kline`; 缺失的股票降级读实盘 `kline_cache`(前复权, 但需标注「未冻结, 可能有复权污染」);
- 除权/脏数据防护沿用 v1 strategy.py: 开盘/高低价相对昨收跳变 > 涨跌停 1.6 倍、相对 MA20 偏离 > 40% 的交易日不成交;
- 指数(沪深300)用现有 `get_index_kline` 东财通道, 同样入 `backtest_kline(idx:)`。

## 5. 模块一: 持仓回测(核心)

### 5.1 模式 A · 真实持仓回测

**输入**: 一键读取 `Position` 表 `status="holding"` 的全部持仓(symbol/name/qty/cost/pyramid_stage/opened_at 天然齐全), 可勾选剔除。

**回放起点**: 每只持仓从 `opened_at`(首仓录入日) 起进入组合, 成本取 `cost`(含费摊薄成本, 与实盘口径一致), 数量取 `qty`, 加仓档位从 `pyramid_stage` 续算。

**三条对照线**(同一初始状态, 只差后续管理策略):

| 线 | 后续管理 | 含义 |
|---|---|---|
| 躺平线 | 买入持有至回测末日 | 实际已发生(真实曲线) |
| 纪律线 | 仅执行 SELL_STOP 止损 | 最简风控底线 |
| 系统线 | 信号全开: 加仓/减仓/止损/做T + 风控闸门 | 完全按系统纪律 |

**产出**:
- 组合净值曲线 ×3 + 沪深300 基准(以各持仓建仓日加权起点对齐);
- 每只持仓单独的三线对比曲线(可直接定位「哪只票该止损没止损」);
- **差异归因表**: 系统线 − 躺平线的超额收益, 拆解到 每只票 × 操作类型(止损/减仓/加仓/做T) 的贡献, 正负分列。

### 5.2 模式 B · 组合回测(多股票、不同时间建仓)

**输入**: 一组建仓腿 `[{symbol, name, entry_date, cost, qty, (pyramid_stage)}]`, 支持:
- **手动输入** 或 **从 Trade 表导入**(按 `action="buy"` 过滤, 自动带出真实价格/日期);
- **同票分批建仓**: 同一 symbol 允许多腿(如 3/1 买 1000 股, 4/15 再加 1000 股), 各腿独立成本;
- 每腿 `entry_date` 可不同 —— 组合按**交易日并集**对齐, 单腿在自身时间轴内索引(停牌/错位自动跳过)。

**后续管理可选**: 买入持有(仅合成组合净值) / 固定止损(可配百分比) / 信号全开(复用模式 A 引擎)。

**产出**: 组合净值曲线 + 每腿贡献占比 + 最大回撤区间定位(哪段行情、哪只票拖累)。

### 5.3 撮合与执行规则(沿用 v1 §4, 与实盘一致)

- 信号日 T 收盘判定 → **T+1 开盘价成交**(滑点默认 0.1% 可配);
- T+1 制度 / 涨停不可买 / 跌停不可卖 / 停牌顺延 / 价格跳变防护(§4.4);
- 费用调用 `compute_trade_fee`, 与实盘口径一致;
- 风控闸门(日亏熔断/连亏降仓/回撤防守)在组合层面生效; 行业限配按 `StockClassification.sw_l1` 接入组合约束(多腿时才有效)。

## 6. 模块二: 信号审计回测(新增)

**目的**: 量化「计划 vs 执行」——真实成交(`Trade` 表, 含 time/price/qty/pnl)逐笔回放, 同时逐日重算信号引擎, 得到两条曲线:

| 曲线 | 口径 |
|---|---|
| 真实曲线 | 按 Trade 表实际买卖(含实际价格/费用/已实现 pnl)合成 |
| 纪律曲线 | 同一持仓起点, 若严格按信号引擎当日判定执行(T+1 开盘价) |

**输出**:
- 两线净值对比 + 偏差总额(纪律曲线 − 真实曲线);
- **逐笔审计表**: 每笔真实交易, 标注「当日系统建议(信号类型/方向/参考价) vs 实际动作(价格/方向)」, 偏差分三类:
  - 违背(系统建议减仓/止损, 实际持有或加仓);
  - 滞后(建议后 N 天才执行, 记录 N 与价差);
  - 提前(未到信号即行动, 记录与信号日的收益差);
- 按股票/按操作类型汇总偏差贡献, 输出「最该改的三笔」提示。

**边界**: 真实成交时间需在 K 线区间内; 区间外交易仅提示不参与回放。

## 7. 模块三: 既有回测升级(准确性修复)

### 7.1 撮合引擎抽取 `backtest/broker.py`

从 strategy.py 抽出独立撮合层: 委托(类型/价格/数量) → 成交判定(T+1/涨跌停/停牌/滑点/费用/碎股) → 成交回报。持仓/资金/风控状态机与撮合解耦, 便于单测与后续多模式复用(持仓回测/审计回测共用)。

### 7.2 做T 口径统一

删除 strategy.py 内联做T 逻辑, 统一走 `SignalEngine._check_t_trade`(唯一事实源); 成交仍按「T-1 收盘布林轨判定 + 当日高低价近似」的用户确认口径, 但判定条件与实盘严格一致。

### 7.3 策略回测参数化

`run_strategy_backtest` 支持: 自定义时间区间(默认用缓存全区间)、**参数覆盖**(`overrides: {止损: {stop_loss_pct: 8}, ...}`, 仅本次回测生效, 不回写配置)、股票池显式指定。

### 7.4 基准对比

全部回测报告默认附带沪深300 同期净值序列(`get_index_kline("0.000300")`), 前端叠加显示; 报告 meta 增加 `excess_return_pct`(相对基准超额)。

### 7.5 任务持久化

新增 `backtest_tasks` 表(任务 id/类型/参数 JSON/状态/进度/结果 JSON/错误/创建时间), 替代内存 `_tasks`; 重启后可查历史任务与结果, 支持清理。

## 8. 撮合与成本模型(沿用 v1 §4)

| 规则 | 约定 |
|---|---|
| 成交时点 | 信号日次日开盘价(做T 用当日高低价近似, 乐观口径需在报告标注) |
| T+1 | 买入当日不可卖出 |
| 涨跌停 | 涨停不可买、跌停不可卖, 该委托作废(按板块 10%/20%/30%) |
| 停牌 | 不撮合, 持仓顺延 |
| 滑点 | 基准价 ×(1 ± 滑点率), 默认 0.1% 可配 |
| 手续费 | `compute_trade_fee(action, amount, cfg)`, 与实盘一致 |
| 复权 | **前复权冻结快照**(§4), 除权跳变日防护不成交 |

## 9. 统计指标

### 9.1 组合维度(持仓回测/策略回测)

`净值曲线 / 最大回撤(金额+比例+区间) / 年化收益 / 夏普 / Calmar / 换手率 / 月胜率 / 超额收益(相对基准)`

### 9.2 单笔维度(沿用 StatsService 口径)

`胜率 / 盈亏比 / 期望值 / 获利因子 / 平均盈 / 平均亏 / 最大连亏 / 最大单笔亏`

### 9.3 差异归因(持仓回测专属)

`超额收益 = Σ(每票 × 每操作类型贡献)`, 表: `[股票 | 操作类型 | 次数 | 贡献金额 | 贡献% ]`

## 10. 防过拟合设计

1. **固定默认参数**: 回测默认读 `config_manager` 当前配置, 覆盖参数需显式声明;
2. **参数敏感性而非最优搜索**: 同一组合批量跑 3×3 网格(止损 5/8/12% × 止盈 1.5/3/5 ATR), 输出热力图, 只高亮「±30% 范围内结果稳健」的参数区间(不做网格寻优);
3. **样本外校验**: 报告区分样本内(参数所在区间)与样本外(后 1/3 区间), 只信样本外结论;
4. **基准对照**: 超额收益为正才值得讨论, 绝对收益无意义;
5. **标注幸存者偏差**: 数据源无历史退市股, 全市场类回测需标注。

## 15. 明确边界

- **回测不是预测**: 过去有效不代表未来有效, 动量因子在风格切换期会连续失效;
- **幸存者偏差**: 历史退市股数据缺失会高估收益, 全市场类回测必须标注;
- **流动性假设**: 回测假设按价成交, 小票真实滑点可能远大于 0.1%;
- **前复权冻结快照的局限**: 区间拉取后冻结, 若后续发生大比例分红送转, 快照与实盘最新前复权价存在换算差(回测口径恒定, 不影响区间内结论);
- **过拟合诱惑**: 任何「看起来完美」的参数组合都不可信, 只信样本外 + 稳健区间结果;
- **做T 乐观口径**: 按当日最高/最低价近似成交, 报告必须标注, 实盘难以精确复现。
