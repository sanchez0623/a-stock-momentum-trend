# 回测中心 — 回测功能设计方案

> 状态: 设计稿 v0.1 · 关联模块: `screener` / `signals` / `indicators` / `datasource.cache` / `fees` / `stats`
> 解决的问题: 「技术面选出来的股票, 后续上涨概率有多大? 买进被套只能割肉吗?」
> —— 回测不能保证未来, 但能把「感觉上的热门」变成「数据上的条件概率」。

---

## 1. 为什么需要回测

### 1.1 先给结论(诚实版)

技术面选股(包括本系统的三因子打分)提供的**不是确定性, 而是概率优势**:

- 动量/趋势类策略的典型历史胜率在 **40%~60%** 之间, 赚钱靠的是**盈亏比**(赚的时候赚得多, 亏的时候亏得少), 而不是高胜率。
- 单看「买进后会不会涨」, 分数越高、信号越强, **条件概率越高**, 但永远到不了 100%。
- 真正决定系统生死的是 **期望值 = 胜率 × 平均盈利 − 败率 × 平均亏损**, 回测要量化的是这个数, 而不是某个「保证」。
- 回测能回答的是「在历史上, 什么条件下买, 期望是正的、回撤是可控的」——这比任何口号都接近「保证」。

### 1.2 回测要回答的三个问题

| 问题 | 回测层次 | 直接产出 |
|---|---|---|
| Q1 不同分数段/关注度的股票, 未来 N 日上涨概率与期望收益差多少? | 因子回测 | 分桶胜率表 |
| Q2 五类信号(首仓/加仓/减仓/止损/做T)触发后的历史表现如何? | 信号回测 | 信号有效性报告 |
| Q3 完整策略(选股+信号+风控+仓位)的历史净值与回撤如何? | 全流程策略回测 | 资金曲线报告 |

MVP 阶段先做 Q1(因子回测)——它能最快回答用户「分高是不是真的更靠谱」, 且不涉及撮合, 实现最轻。

## 2. 现状基础: 这套系统的回测可行性

本项目回测的可行性**远高于一般系统**, 因为核心逻辑全部是**纯函数、确定性计算**, 天然可回放:

| 资产 | 位置 | 回测中的角色 |
|---|---|---|
| 指标计算 `compute_all()` | `backend/app/core/indicators/` | 输入历史 K 线 → 指标列(纯函数, 无状态) |
| 三因子评分 `score_indicators(ind, cfg)` | `backend/app/core/screener/engine.py` | 对任意历史日回放打分(纯函数) |
| 信号引擎 `SignalEngine.evaluate()` | `backend/app/core/signals/engine.py` | 逐日判定五类信号(纯函数, 优先级: 止损>减仓>加仓>首仓>做T) |
| 市场闸门 `compute_market_gate()` | `backend/app/core/market_gate.py` | 回测中每日环境判定 |
| 行业限配 `apply_per_industry_cap()` | `backend/app/core/classification.py` | 组合层面约束 |
| 手续费 `compute_trade_fee()` | `backend/app/core/fees.py` | 成本模型(佣金万0.5最低5元 + 印花税万5卖方 + 三费) |
| 统计口径 `StatsService.summary()` | `backend/app/core/stats/service.py` | 胜率/盈亏比/期望/最大连亏, 直接扩展 |
| K线缓存 `kline_store` | `backend/app/core/datasource/cache.py` | 回测历史数据源(SQLite `kline_cache`, 日线上限 800 根) |
| 配置中心 `config_manager` | `backend/app/core/config.py` | 回测与实盘强制同参数, 防「纸上赚实盘亏」 |

**结论: 回测引擎不需要重写任何选股/信号逻辑, 只需要新增一个「历史回放 + 撮合 + 统计」层。**

---

## 3. 回测对象: 三个层次

### 3.1 因子回测(MVP, 最轻)

- 不做撮合, 只做统计: 对历史每个交易日的每只股票算出分数, 记录**信号日之后 1/3/5/10/20 日的收益率**。
- 按维度分桶对比: 分数段(≥85 / 70~85 / 60~70 / 50~60)、关注度、RSI 区间、乖离率区间、ADX 区间、市场环境(闸门三态)。
- 直接产出:
  - 「69.1 分(重点观察) vs 85 分(强烈关注)」的胜率与平均收益差异;
  - 「RSI 75+ 追高 vs RSI 55~65 回踩」哪个更安全(用数据说服自己别追高);
  - 乖离 >10% 时买入的套牢概率。

### 3.2 信号回测(V1)

- 逐日回放 `SignalEngine.evaluate()`, 记录每条历史信号(含持仓上下文)。
- 统计每类信号的**触发后表现**:
  - `BUY_FIRST` 后 5/10 日的胜率与均值;
  - `SELL_STOP` 触发后, 股价是否继续下跌(验证止损有没有「割在地板上」);
  - `SELL_REDUCE` 与直接 `SELL_STOP` 的收益对比(验证「先减仓」优于「死扛到止损」);
  - 做T 信号的平均日内收益(验证降成本可行性)。

### 3.3 全流程策略回测(V2)

- 事件驱动逐日回放: 每日跑选股 → 按信号建仓/加仓/减仓/止损 → 按仓位策略(pyramid/kelly/fixed)分配资金 → 每日结算净值。
- 联动实盘风控: 市场闸门缩放仓位、行业限配约束组合、风控三道闸(日亏熔断/连亏降仓/回撤防守)全部生效。
- 产出: 净值曲线、回撤曲线、换手率、年化/夏普/Calmar、最大连亏、交易明细。

## 4. 撮合与成本模型(防未来函数的关键)

回测最常见的错误是「未来函数」——用当天收盘才知道的数据, 假装当天就能交易。本方案硬性约定:

| 规则 | 约定 | 原因 |
|---|---|---|
| 成交时点 | **信号日次日开盘价**成交(或次日收盘价, 可选) | 信号由当日收盘数据算出, 当日不可成交 |
| T+1 | 买入当日不可卖出 | A股制度 |
| 涨跌停 | 涨停价无法买入、跌停价无法卖出, 该委托作废 | 否则会回测出不可能的交易 |
| 停牌 | 停牌日不撮合, 持仓顺延 | 否则产生虚假流动性 |
| 滑点 | 成交价 = 基准价 × (1 ± 滑点率), 滑点率默认 0.1%, 可配置 | 真实成交总有冲击成本 |
| 手续费 | 直接调用 `compute_trade_fee(action, amount, cfg)` | 与实盘口径完全一致 |
| 复权 | **必须使用后复权数据**(前置依赖, 见 §8) | 不复权会让除权日出现假暴跌, 误触发止损 |

## 5. 统计指标

### 5.1 单笔维度(复用并扩展 `StatsService.summary`)

`胜率 / 盈亏比 / 期望值(每笔平均收益) / 获利因子 / 平均盈 / 平均亏 / 最大连亏 / 最大单笔亏`

### 5.2 组合维度(策略回测)

`净值曲线 / 最大回撤(金额+比例+区间) / 年化收益 / 夏普 / Calmar / 换手率 / 月胜率`

### 5.3 分桶对比(因子回测的核心产出)

| 桶 | 样本数 | 胜率(N日) | 平均收益 | 中位数 | 期望(扣除费用) |
|---|---|---|---|---|---|
| 总分 ≥ 85 | … | … | … | … | … |
| 70~85 | … | … | … | … | … |
| 60~70 | … | … | … | … | … |
| 50~60 | … | … | … | … | … |

> 判读准则: **只看期望值**, 胜率 50% 但盈亏比 1:1.8 的策略依然赚钱; 胜率 70% 但盈亏比 1:0.5 的策略照样亏钱。

## 6. 防过拟合设计

1. **固定默认参数回测**: 回测直接读 `config_manager` 当前配置, 不与实盘脱节;
2. **样本内/样本外切分**: 前 2/3 校准, 后 1/3 验证, 只有样本外也成立的结论才写进报告;
3. **Walk-forward 滚动窗口(V3)**: 每 60 交易日重训一档, 拼接成样本外净值曲线;
4. **参数敏感性而非最优搜索**: 只输出「阈值 ±30% 范围内结果是否稳健」, 不做网格搜索挑最优参数(最优=过拟合的代名词);
5. 结论只取**稳健区间**, 回测报告里高亮「该结论对参数不敏感」的因子。

## 7. 架构设计

### 7.1 后端新模块 `backend/app/core/backtest/`

```
backtest/
├── data.py       # 历史数据加载: kline_cache 存量 + 补拉(后复权), 指数/行业/成分表
├── broker.py     # 撮合: 委托簿/次日开盘成交/T+1/涨跌停/停牌/滑点/手续费(调用 fees.compute_trade_fee)
├── strategy.py   # 策略装配: 复用 score_indicators + SignalEngine + 市场闸门 + 行业限配 + 仓位/风控
├── engine.py     # 回测主引擎: 事件驱动逐日回放, 输出交易明细 + 每日净值
├── metrics.py    # 统计指标: 复用/扩展 StatsService 口径 + 组合指标
├── report.py     # 报告组装: 汇总 + 分桶表 + 净值/回撤序列(JSON, 供前端图表)
└── task.py       # 后台任务管理: 回测跑批可中断/可查询进度(全市场逐日回放计算量大, 必须异步)
```

### 7.2 API 设计(异步任务)

| 接口 | 说明 |
|---|---|
| `POST /api/backtest/run` | 提交回测(参数: 时间范围/选股配置/信号开关/成本参数), 返回 task_id |
| `GET /api/backtest/tasks/{id}` | 查询进度(阶段/百分比/已回放股票数) |
| `GET /api/backtest/tasks/{id}/report` | 拉取完成后的报告(汇总 + 分桶表 + 序列数据) |
| `POST /api/backtest/cancel/{id}` | 中断长任务 |

统一走现有 `{code, msg, data}` 包络与 `/api` 前缀。任务状态持久化到 SQLite(新建 `backtest_tasks` 表), 重启可查历史任务。

### 7.3 前端: 回测中心页面

- 入口: 左侧导航新增「回测中心」;
- 表单: 回测区间、N 日持有、分桶维度、成本参数(滑点/手续费开关)、是否跑信号/全流程;
- 运行态: 进度条 + 阶段日志;
- 报告页: 分桶胜率表、净值/回撤曲线(复用现有图表组件或 echarts)、信号统计、交易明细可导出 CSV。

## 8. 数据准备(前置条件)

| 项 | 现状 | 回测需求 | 动作 |
|---|---|---|---|
| 个股日线 | `kline_cache` 日线上限 800 根(~3.2 年) | 5 年 ~1200 根, **后复权** | 补拉 + 扩展 `_MAX_ROWS["daily"]` 或独立 `backtest_kline` 表 |
| 复权 | 缓存未标注复权口径, 需核实数据源实现 | 必须后复权 | **前置确认项**: 检查 mootdx/tencent/baostock 的复权参数, 回测库单独存复权数据, 不污染实盘缓存 |

| 股票池 | `stocks` 表缓存 | 历史区间内的存续股票 | 注意**幸存者偏差**: 需记录历史退市股(数据源能力有限, MVP 阶段先接受偏差并标注) |
| 行业分类 | `StockClassification` 表 | 限配分组 | 直接复用 |
| 历史事件/基本面 | `fundamentals` 表(仅近期) | 历史事件不可得 | MVP 关闭基本面因子, 只回测技术因子 |

## 9. 实施路线

| 版本 | 范围 | 交付 | 预估工作量 |
|---|---|---|---|
| MVP | 因子回测(§3.1) | 分桶胜率报告, 回答「分高是否更靠谱」「追高 vs 回踩」 | 小 |
| V1 | 信号回测(§3.2) | 五类信号有效性 + 止损有效性验证 | 中 |
| V2 | 全流程策略回测(§3.3) | 净值/回撤/风控联动 | 中 |
| V3 | walk-forward + 参数敏感性(§6) | 稳健性报告 | 小 |

> 建议顺序执行: MVP 先上线, 用真实历史数据回答用户最关心的「概率」问题; 结论稳健后再上 V1/V2, 避免一开始就陷入复杂撮合调试。

## 10. 专题: 「买入被套, 只能割肉吗」的回测验证方向

用户痛点不是「要不要止损」, 而是「止损是不是唯一手段」。回测 V1 阶段专门设计四组对比实验:

1. **固定止损 vs 移动止损 vs 时间止损**: 哪种退出方式的期望值最高、回撤最小?(时间止损: 入场 N 日不涨则退出)
2. **减仓(半仓) vs 直接止损**: 信号引擎的 `SELL_REDUCE` 是否优于死扛到 `SELL_STOP`?
3. **做T 降成本效果**: 高波动持仓中做 T 平均能降多少成本、是否能对冲短期被套?
4. **回踩买入 vs 追高买入**: 验证「RSI 健康区 + 乖离 <5% 入场」是否显著优于「RSI>75 + 乖离 >10% 追高」。

这四组实验的答案, 就是把「割肉」升级为「分层退出 + 主动管理」的数据依据。

## 11. 明确边界: 回测不能保证什么

- **回测不是预测**: 过去有效不代表未来有效, 市场风格会切换(动量因子在风格切换期会连续失效);
- **幸存者偏差**: 历史退市股数据缺失会高估收益, MVP 阶段必须标注;
- **流动性假设**: 回测假设可以按价成交, 小票真实滑点可能远大于假设;
- **过拟合诱惑**: 任何「看起来完美」的参数组合都不可信, 只信样本外结果。
